1 / 8프로젝트와 부품 준비

STM32가 거리 측정과 현장 제어를 맡는다. PC는 키트의 USB 직렬 포트로 명령을 보내고, 별도 보드인 ESP32-L은 STM32가 보내는 상태와 위치를 전자종이에 그린다.

작업대에 놓을 것

한백전자 HBE-MCU-MULTI 키트(STM32F103RBT6·UART·LED·PIEZO·4×3 키패드), 3.3 V 구동형 HC-SR04P 5개, SG90 서보, Good Display ESP32-L·DESPI-C02·전자종이 패널을 준비한다.

배선용 브레드보드와 점퍼선, 센서 5개용 3.3 V 정전압 전원, 서보 정격 전원, 보드 단자에 맞는 USB 데이터 케이블, 줄자와 평평한 표적, 도통·전압 확인용 계측기가 필요하다. 펄스 높이는 오실로스코프로 확인한다.

어느 단자에 몇 V를 공급할까?

선정한 3.3 V 구동형 HC-SR04P는 다섯 개 모두 3.3 V로 공급한다. 각각의 VCC를 같은 빨간 + 레일로, 각각의 GND를 같은 − 레일로 잇는다. 센서 전원 음극과 STM32 J5-4도 − 레일로 간다.

2 / 8센서의 GND부터 꽂기

S1~S5의 VCC는 각각 3.3 V다. USB와 외부 전원을 분리하고 각 센서에 S1~S5 표시를 붙인다. 센서마다 기판에 인쇄된 VCC, GND, TRIG, ECHO를 찾아 네 가닥을 연결한다.

  1. 공통 GND. STM32의 J3 소켓과 MCU 칩 사이 검은 2×10 헤더가 J5다. 기판의 1번 표시 맞은편이 2번이고, 그 옆 같은 열이 4번이다. 빈 J5 4번을 브레드보드의 − 레일로 잇는다. 센서 전원 음극과 다섯 센서의 GND도 이 레일에 꽂는다.
  2. 센서 전원. 센서용 3.3 V 전원 양극을 + 레일에 연결하고 각 VCC를 그 레일에 꽂는다. 외부 전원 양극은 센서 레일에만 연결한다. 레일이 중간에 끊겼으면 전원을 끈 상태에서 도통을 확인해 같은 극끼리 잇는다.
  3. TRIG와 ECHO. TRIG는 순서대로 PC8 / PC9 / PC10 / PC11 / PC12(J4 왼쪽)다. ECHO는 PA0 / PA1 / PA2 / PA3(J3 왼쪽), PB6(S5·J3 오른쪽)다. S1부터 한 쌍씩 표시를 대조한다.
ECHO를 STM32에 연결하기 전 · 보드와 센서 GND를 공통으로 하고 ECHO 선의 MCU 쪽 끝을 분리한 채 센서를 구동한다. 보드에 측정 펌웨어가 없으면 5단계에서 먼저 전송한다. 오실로스코프의 GND를 공통 GND에 두고 표적 응답의 HIGH가 3.3 V 수준인지 확인한다. 5 V 출력이면 3.3 V용 레벨 변환을 적용하고 다시 측정한다. 전원을 끈 뒤 ECHO 선을 꽂는다.

J3·J4 소켓 및 J5 번호는 실습자료 「실험1-GPIO-InputOutput」 20~21쪽 기준이다. ST STM32F103RB 핀 정의

브레드보드에서 네 가닥의 자리 찾기

센서 머리를 복도에 설치할 때는 암–수 점퍼로 센서의 네 단자를 보드 구멍에 옮겨 꽂는다. 아래 그림은 30번까지 있는 브레드보드에서 같은 번호의 A~E끼리 도통되는 쪽을 쓴 예다. 실물 표기와 구멍끼리의 도통을 전원 연결 전에 확인한다.

다섯 센서의 VCC·TRIG·ECHO·GND를 차례로 꽂을 자리는 S1 E3~E6 · S2 E9~E12 · S3 E15~E18 · S4 E21~E24 · S5 E27~E30이다. 레일과 A~E 신호 구멍은 그림처럼 점퍼로 이어야 전원이 전달된다.

3 / 8ESP32-L과 전자종이 연결

전원을 분리하고 ESP32-L을 USB 단자가 위, 빨간 버튼이 오른쪽 위에 오도록 놓는다. STM32와 연결할 곳은 빨간 버튼 바로 아래 오른쪽 위 노란 10구 커넥터 P6다. 왼쪽 중간의 노란 8구는 별도의 커넥터 P9이며 이 배선에서는 비워 둔다.

UART 점퍼 3개를 ESP32-L 커넥터 P6에 꽂기

커넥터 P6의 9번 핀에서 P6는 오른쪽 위 커넥터의 이름이고 9번은 그 안의 핀 번호다. 회로도상 핀 번호는 위에서부터 10·9·8·7 순서다.

커넥터위에서기판 인쇄핀 번호연결할 STM32 단자
P6첫 번째SCL10번PB11 · ESP32 GPIO22가 송신, STM32가 수신
P6두 번째SDA9번PB10 · STM32가 송신, ESP32 GPIO21이 수신
P6세 번째3V38번비워 둔다.
P6네 번째GND7번STM32 GND와 연결된 브레드보드 − 레일

보드 간 신호는 3.3 V TTL, 115200 baud, 8N1이다. ESP32 펌웨어는 SDA를 UART2 수신, SCL을 UART2 송신으로 배정한다. P6 아래쪽의 TX·RX 표기 핀은 USB 직렬 회로에 연결되므로 이 단계에서는 비워 둔다. 두 보드는 각각 자체 전원을 쓰고 이 세 가닥만 연결한다.

전자종이 패널과 어댑터

  1. 패널 뒷면이나 지급 명세에서 GDEY075Z08(800×480, 흑·백·적)을 확인한다. FPC-C001은 리본의 표기다. 모델을 확인한 뒤 이 패널의 DESPI-C02 RESE를 0.47 Ω로 맞춘다.
  2. 패널 리본을 DESPI-C02 커넥터 P1에 곧게 삽입해 잠근다. ESP32-L 하단 검은 커넥터 P5와 DESPI-C02의 8핀 커넥터 P2에서 각 1번 핀의 3.3V 인쇄를 맞추고, 3.3V → GND → SDI → SCK → CS → D/C → RES → BUSY 순서가 서로 맞게 연결한다.

5 / 8STM32를 빌드하고 키트에 넣기

① IAR에서 HEX 만들기

  1. 수업용 Windows PC에서 IAR Embedded Workbench for Arm을 열고, File → Open → Workspace에서 압축을 푼 stm32\Getting_start.eww를 선택한다.
  2. 워크스페이스의 빌드 구성을 EMB_FLASH로 선택한다. Project → Rebuild All을 실행하고 Build 창에서 오류 0건을 확인한다. 이 프로젝트의 C 코드는 동봉된 STM32F10x SPL V1.0으로 빌드된다.
  3. 탐색기에서 stm32\EMB_FLASH\Exe\Getting_start.hex의 수정 시각이 방금 빌드한 시각인지 확인한다.
다른 PC에서 “non-native line endings”가 뜰 때 · 최신 저장소를 새 폴더에 받아 압축을 모두 푼 뒤 그 폴더의 .eww를 연다. 이 프로젝트의 STM32 소스와 IAR 프로젝트 파일은 Windows용 CRLF 줄 끝으로 배포한다. 기존에 수정한 파일은 먼저 별도 보관한다.

② DFU File Manager로 HEX 변환

  1. 수업용 ST DFU File Manager에서 DFU 파일을 만드는 항목(I want to GENERATE a DFU file…)을 선택한다.
  2. S19 or Hex…에서 위의 Getting_start.hex를 선택한다. Generate를 눌러 이번 빌드의 Getting_start.dfu를 구별되는 폴더에 저장한다.

③ DfuSe Demo로 쓰기

  1. 키트의 MCU Power를 끈다. STM32 MCU 모듈의 USB를 PC에 연결한다. PROG를 누른 채 MCU Power를 켠다. DfuSe Demo의 장치 목록에서 키트를 확인한 뒤 PROG를 놓는다.
  2. DfuSe Demo의 Upgrade or Verify Action → Choose에서 방금 만든 DFU를 연다. File correctly loaded 문구, 키트의 내부 Flash 대상, 선택한 파일명을 확인한 후 Upgrade를 실행한다.
  3. Upgrade successful이 나올 때까지 USB와 전원을 유지한다. 완료되면 PROG를 누르지 않은 상태에서 MCU USB 아래 RESET을 눌러 애플리케이션을 시작한다. PC 명령은 7단계의 UART 모듈 포트에서 보낸다.
시작 주소는 0x08003000 · 키트의 기존 USB 부트로더 영역을 보존하는 프로젝트다. 이 절차에는 전체 플래시 지우기나 주소 재지정이 필요하지 않다. 장치 목록이 비면 MCU 모듈 USB, 데이터 케이블, DFU 드라이버와 PROG·전원 순서부터 점검한다.

키트 실습자료 「01_GPIO_Output」 슬라이드 15~27의 절차. 교재의 DFU File Manager·DfuSe Demo 화면은 v3.0.0이다. ST DfuSe 도구

6 / 8ESP32-L을 빌드하고 전송하기

Arduino CLI와 Espressif 보드 코어 2.0.17을 사용한다. 초기 설치와 첫 빌드에는 인터넷이 필요하다. 빌드 스크립트가 Good Display 공식 ESP32epdx의 고정 커밋에서 GDEY075Z08 드라이버를 받는다.

① PowerShell에서 빌드

  1. Windows용 arduino-cli.exe를 설치하고 PATH에서 실행되도록 준비한다. PowerShell에서 arduino-cli version으로 설치를 확인한다. Arduino CLI 공식 설치 안내
  2. 파일 탐색기에서 stm32와 esp32가 보이는 저장소 폴더를 연다. 주소 표시줄에 powershell을 입력하고 Enter를 누른 뒤 아래 명령을 순서대로 실행한다.
cd .\esp32
$index = 'https://espressif.github.io/arduino-esp32/package_esp32_index.json'
arduino-cli core update-index --additional-urls $index
arduino-cli core install esp32:esp32@2.0.17 --additional-urls $index
arduino-cli core list
.\build.ps1

core list의 esp32:esp32가 2.0.17인지 본다. 빌드가 끝나면 esp32\.build\bin에 바이너리가 생긴다. 대상은 클래식 ESP32(esp32:esp32:esp32)다. ESP32-S는 사진 속 모듈의 표기다.

② 실제 ESP32 포트로 업로드

  1. USB를 연결하기 전 arduino-cli board list를 실행한다. ESP32-L의 USB에 데이터 케이블을 연결하고 전원 스위치를 켠 뒤 다시 실행해 새로 나타난 COM 번호를 찾는다. 업로드할 포트를 열고 있는 터미널은 닫는다.
  2. 아래 COM5 자리에 확인한 번호를 넣고 같은 esp32 폴더에서 실행한다. 빌드와 업로드가 성공한 다음 화면에서 첫 전체 갱신이 끝날 때까지 기다린다.
.\build.ps1 -UploadPort COM5
포트 용도 · ESP32-L의 USB는 이 보드의 업로드·진단용이다. 다음 단계의 RAW와 관제 명령은 키트 UART 모듈의 COM 포트로 보낸다.

7 / 8보정 전에 거리와 관제 명령 시험

① 터미널 포트와 줄 끝 맞추기

키트 UART 모듈의 USB를 PC에 연결하고 장치 관리자 ‘포트(COM 및 LPT)’에서 해당 번호를 확인한다. HyperTerminal 등 직렬 터미널에서 그 포트를 9600 baud, 데이터 8비트, 패리티 없음, 정지 1비트, 흐름 제어 없음으로 연다. 대문자 ASCII 명령을 한 줄씩 입력하고 Enter를 누른다. CR·LF·CRLF 줄 끝을 모두 받는다.

② 센서를 하나씩 확인

  1. RAW를 입력한다. 응답에서 R 뒤의 다섯 수가 차례로 S1, S2, S3, S4, S5의 거리(mm)다. -1은 아직 유효한 ECHO가 없거나 시간 안에 받지 못했음을 뜻한다.
  2. S1 앞 평평한 표적을 가까이·멀리 옮기고 약 1초씩 간격을 두어 RAW를 다시 보낸다. 첫째 수가 변하는지, 줄자 거리와 어느 정도 차이 나는지 기록한다. S2~S5도 해당 열을 각각 확인한다.
RAW
R,205,610,-1,440,320

형식을 보여 주는 예시다. 여기서 205는 S1의 205 mm, -1은 S3의 미측정이다. 실제 숫자는 표적과 배치에 따라 달라진다.

CAUTIONOK점멸 / 꺼짐CAUTION
DANGEROK동시에 점멸DANGER
ARRIVEDOK둘 다 켜짐ARRIVED

점멸 간격은 켜짐과 꺼짐이 각각 500 ms다. 각 명령 뒤 화면이 갱신될 시간을 준다. 모르는 명령에는 ERR COMMAND가 돌아온다. 초기 설정에서 예상되는 표시는 다음과 같다.

POSITION UNKNOWN   NO FIX
CMD SAFE   S5 UNKNOWN   DOOR UNSET

처음 켰을 때 명령은 NONE이고 위 예시는 SAFE 입력 뒤다. ARRIVED로 LED 두 개가 켜져도 서보 끝점을 보정하기 전에는 서보 펄스를 출력하지 않는다.

값이 안 나오면 · 아무 응답도 없으면 키트 UART 포트·9600·줄 끝·PA9/PA10을 본다. 한 열만 계속 -1이면 그 센서의 전원·공통 GND·TRIG/ECHO·표적 방향을 확인한다. 화면에 STM32 STATUS UNAVAILABLE가 계속 뜨면 STM32 PB10 → ESP32-L 커넥터 P6의 위에서 두 번째 구멍(SDA, 9번 핀)과 공통 GND부터 확인한다.

8 / 8실측값을 넣고 모형 시연

stm32\site_profile.h를 열고 아래 순서로 실제 측정값을 기록한다. 길이는 mm, 서보 펄스 폭은 µs다. 거리·배치·경보·문 끝점은 기본값 0으로 제공된다.

실측 대상기록할 값
다섯 센서의 유효 범위반복 측정이 되는 공통 최소·최대 거리를 SITE_RANGE_MIN_MM / SITE_RANGE_MAX_MM에 입력한다.
복도 1~4site_corridors[0..3]에 원점(x,y), 방향(dx,dy), 복도 길이, 거리 오차 보정량, 빈 복도 배경 거리, 표적 판별 여유를 입력한다. 오른쪽 +x, 아래 +y이며 방향은 한 축에 +1 또는 −1을 준다.
움직이는 표적모형의 최대 속도와 위치 오차를 SITE_MAX_SPEED_MM_S / SITE_POSITION_ERROR_MM에 입력한다.
위험지점 S5유효 범위 안에서 접근 거리 SITE_HAZARD_ON_MM, 더 큰 해제 거리 SITE_HAZARD_OFF_MM, 연속 판정 횟수 SITE_HAZARD_SAMPLES를 정한다.
서보·문문 링크를 분리한 상태에서 정격과 실제 허용 이동 범위를 확인하고 닫힘·열림 펄스 폭을 SITE_SERVO_CLOSED_US / SITE_SERVO_OPEN_US에 넣는다. 실물 허용 범위 안에서 서로 다른 값이어야 한다.
보정값을 바꾼 뒤 두 보드 모두 다시 빌드하고 전송한다. ESP32 빌드도 STM32 폴더에서 같은 좌표 설정을 읽는다. STM32에는 새 HEX에서 다시 만든 DFU를 넣는다.

최종 확인 순서

  1. 복도와 화면. 모형 하나를 S1~S4 복도에서 옮긴다. 한 복도에서 위치가 결정되면 해당 복도와 mm 좌표가 POSITION으로 표시된다. CHECK MAP이면 송신된 좌표와 화면의 축·길이 설정을 대조한다.
  2. S5와 피에조. 표적을 접근 거리 안으로 옮겨 설정 횟수만큼 유지한다. ACTIVE와 부저음을 확인한다. 해제 거리 밖에 유지하면 CLEAR와 함께 소리가 꺼진다. 알람 중 유효 ECHO를 잃으면 ACTIVE_FAULT와 소리가 유지된다.
  3. 키패드와 문. 보정 후 리셋하면 닫힘 위치에서 시작한다. SAFE 상태에서 키패드 0을 눌렀다 놓고 문이 닫혀 있는지 확인한다. ARRIVED를 보내 OK를 받은 뒤 0을 새로 누른다. 문이 한 번 열리고 상태는 OPEN을 유지한다.
  4. 보드 간 UART. 화면 갱신 중에도 RAW와 LED가 반응하는지 본다. ESP32는 약 2.5초간 새 프레임을 받지 못하면 해당 표시를 미확인으로 바꾼다. 눈으로 보이는 변화에는 패널 갱신 시간이 더 걸린다.

선 분리 시험 · 두 보드 전원을 모두 끈 상태에서 STM32 PB10에서 ESP32-L 커넥터 P6의 SDA(위에서 두 번째, 9번 핀)로 가는 선만 분리하고 각 보드를 다시 켠다. ESP32에 STM32 STATUS UNAVAILABLE가 남는지 본다. 다시 전원을 끄고 원래대로 연결한 뒤 상태 수신을 확인한다.

현재 기록된 검증은 STM32·ESP32 빌드, PC에서의 타이머 입력 주입과 UART 프레임 해석이다. 배선한 두 보드의 통신, 실제 ECHO 전압·거리, 문 끝점과 전자종이 잔상은 이 모형에서 확인할 항목이다. 근거 파일은 저장소의 stm32/hardware.c, stm32/main.c, stm32/site_profile.h, esp32/ControlRoom, docs/하드웨어_연결.md이다.
