# 2조 위험구역 작업자 추적 관제실 — 진행 현황

2026-11-18 기준. 대상은 모형 작업자 1명, 복도 센서 S1~S4, 위험지점 센서 S5다.

## 완료한 작업

| 항목 | 결과 |
| --- | --- |
| Arduino IDE에서 열기 | 실습 PC의 Arduino IDE 2.3.11에서 ESP32 Dev Module과 Espressif 2.0.17 코어를 사용한다. 다른 PC에서는 `esp32/build.ps1 -PrepareIde`가 출력한 `ControlRoom.ino`를 연다. |
| STM32 | 한백전자 STM32F103RBT6용 C 펌웨어를 실습 자료의 STM32F10x SPL V1.0과 IAR 프로젝트에 통합했다. DFU 벡터 주소는 `0x08003000`이다. |
| 센서와 현장 제어 | 초음파 5개를 순차 측정한다. 키트 UART의 `RAW` 응답은 S1~S5 거리(mm)이며 무응답은 `-1`이다. S5는 부저를 제어한다. 경보가 꺼졌을 때 ECHO가 복구되면 거리 판정에 따라 `UNKNOWN`, `CLEAR`, `ACTIVE` 중 하나로 전환한다. S5 복구 검사는 PC에서 11/11 통과했다. |
| ESP32와 전자종이 | 사진으로 GooDisplay ESP32-L과 DESPI-C02를 확인했다. 계획서의 GDEY075Z08을 대상으로 Good Display 공식 예제에 지도·위치·위험 표지를 연결했다. |
| STM32 피에조 시험판 | 실습 키패드와 PA6 PWM을 사용한다. 숫자 1~5 하나를 누르면 선택 센서의 새 유효 ECHO마다 40 ms 확인음을 낸다. 미보정 상태에서도 작동하며 S5 위험 경보의 연속음이 우선한다. 다섯 키, 무응답, 키 해제·전환, 기존 0 키와 경보 우선순위를 호스트에서 검증했다. |
| 빌드·전송 | STM32 IAR `EMB_FLASH` 클린 빌드 오류·경고 0건. 새 `C:\mcu\ControlRoom_STM32_센서검증.dfu`는 주소 0x08003000부터 15,876바이트다. 정적 SRAM 할당은 스택 예약을 포함해 1,940바이트다. 기본 미보정 상태에서 기존 시험판과 DFU 바이트가 같다. 실측값을 넣으면 S5 복구 수정이 적용되므로 다시 빌드한다. STM32 전송·실행은 사용자가 진행한다. ESP32 교체 보드(CH340 COM4, ESP32-D0WD rev.1.1)에 검정→흰색→지도 고정 버전을 Arduino CLI로 전송했다. 빌드 크기는 플래시 288,481바이트·정적 RAM 21,712바이트다. |
| 센서 입력 캡처 검증 | S1~S5 각각에 타이머 입력을 주입했다. 16비트 카운터 순환을 포함한 5,800 µs 펄스를 다섯 채널 모두 995 mm로 환산했다. 30 ms 기한 뒤 끝난 ECHO가 유효 거리로 처리되던 문제를 수정했다. 입력 캡처 65개와 관제·UART 65개 검사가 모두 통과했다. |
| UART 검증 | STM32 코드가 출력한 위치·상태 7줄을 PC에서 1~5바이트로 나눠 실제 ESP32 수신 코드에 전달했다. 손상 3줄을 폐기하고 별도 파서 시험에서 잘못된 입력 18개를 거부했다. ESP32가 출력한 `READY → ERROR → READY`를 STM32 수신 코드에 다시 전달해 상태 전송 2회와 키트 UART의 `ERR DISPLAY` 1회를 확인했다. 49.7일 이상 끊긴 경우에도 오래된 상태와 위치가 다시 나타나지 않았다. |
| 배선·배치 도면 | 펌웨어의 `stm32/hardware.c`에 있는 `sensor_pins[]`가 S1~S5의 GPIO 초기화와 타이머 입력 캡처를 함께 결정한다. 센서·보드별 배선표, 하드웨어 신호 구조도, 복도 센서·문·관제소의 배치 예시를 [하드웨어 연결 문서](https://github.com/tokengeoji/mcu/blob/main/docs/%ED%95%98%EB%93%9C%EC%9B%A8%EC%96%B4_%EC%97%B0%EA%B2%B0.md)에 정리했다. |
| 초음파 센서 결선 | 실습자료 20~21쪽과 펌웨어를 대조해 J5 4번 접지, 브레드보드의 VCC·GND 분배와 소켓별 TRIG·ECHO 위치를 [확대용 결선도](https://github.com/tokengeoji/mcu/blob/main/docs/ultrasonic-wiring.svg)에 표시했다. 센서 5개 전원 용량과 실제 ECHO 전압은 실물 시험 항목이다. |
| 다른 PC에서 빌드 | GitHub ZIP의 STM32 소스·설정 48개가 CRLF임을 확인했다. Git 개행 설정 3종(false/input/true)으로 새로 복제해도 결과가 같았다. 다운로드한 ZIP을 공백이 있는 다른 경로에 풀어 STM32 IAR 0오류·0경고, ESP32 278,857바이트로 다시 빌드했다. |
| 조립 가이드 | 오프라인 HTML에 브레드보드 구멍 예시, 현장 모듈별 결선, 두 보드의 통신과 전자종이 배선, 보정과 코드 동작 확인 절차를 수록했다. 프로젝트에서 `docs/처음부터_따라하기.html`을 연다. |
| 노션 | 기존 마프 페이지의 흐름·배선계획 HTML을 개정본으로 교체했다. ESP32-L 실물 커넥터, 센서 배선, UART 명령과 실제 빌드 결과를 반영했다. |
| GitHub | 펌웨어와 양쪽 빌드 안내를 `tokengeoji/mcu`의 `main`에 올리고 커밋을 확인했다. |

교체 전 보드의 USB 로그에는 STM32의 위치(P)·상태(S) 수신과 흰색 지우기의 BUSY 응답 누락이 기록됐다. 교체 직후에는 지도 갱신에서 BUSY 10,159 ms를 기록했고 사용자가 지도와 이전 그림의 잔상을 확인했다. 이후 검정·흰색을 거친 직전 버전에서는 사용자가 부팅 직후 지도가 선명했다가 아래부터 흐려지는 현상을 확인했다. 최신 고정 버전의 실제 BUSY 시간은 검정 10,158 ms, 흰색 10,159 ms, 지도 10,160 ms였다. 실제 ESP32에 `?`를 보내 고정 직후와 90.1초 후 두 번 모두 `mode=HOLD completed refreshes=3`을 확인했다. 호스트에서는 가상 20분 동안 실제 수신 코드로 가변 위치·상태 4,002개를 받으면서 최초 지도 1회만 그렸고, U에서 최신값과 단절, H에서 지도 재고정, 첫 구동 실패 후 180초 뒤 복구를 검증했다. [부팅 화면 렌더링](https://github.com/tokengeoji/mcu/blob/main/docs/epaper-startup.png)에서 S1 빨간 시작점을 확인했다. 이 부팅 로그에는 STM32 위치·상태 수신 메시지가 없었다. 최신 화면의 잔상, 실제 UART 왕복, 센서 거리·피에조 소리·서보 동작은 실물에서 확인할 항목이다. 실물에서 U로 전환했을 때 상단·하단 흑백 영역 두 곳의 갱신을 3.2초 만에 확인했다(누계 3→5). H로 고정 지도를 다시 그릴 때 전체 갱신 BUSY는 10.159초였고 누계는 6이 됐다. 같은 지도를 주기적으로 반복 전송하지 않는다.

## 남은 TODO와 시험 순서

1. **부품·전원 확인** — 전원을 끈 상태에서 배선한다. HC-SR04P의 ECHO 전압을 확인한 뒤 STM32에 연결한다. ESP32-L과 DESPI-C02는 사진으로 식별했고, 패널 뒷면 제품 라벨은 계획서의 GDEY075Z08과 대조해야 한다.
2. **센서 5개 단품 시험** — 새 DFU를 실행하고 PA6을 PIEZO 입력에 연결한 뒤 키패드 1~5 중 하나를 누른 채 해당 센서 정면에 평평한 표적을 댄다. 키트 UART에서 9600 baud, 8N1로 `RAW`를 보내 대응 열의 거리 변화를 줄자와 비교한다.
3. **모형 보정** — 빈 복도와 표적이 있을 때의 거리, 센서 원점·방향·복도 길이를 잰다. S5 접근·해제 거리와 서보의 열림·닫힘 펄스 폭도 실측해 `stm32/site_profile.h`에 넣고 두 보드를 다시 빌드한다. 현재 기본값은 미보정이며 거리 원시값을 먼저 읽을 수 있다.
4. **실제 보드 간 UART** — ESP32-L의 USB-C를 위로 두고 오른쪽 빨간 버튼 아래의 노란 커넥터 P6를 찾는다. 위에서 첫째 SCL(10번 핀)에 STM32 PB11, 둘째 SDA(9번 핀)에 PB10, 넷째 GND(7번 핀)에 공통 GND를 꽂는다. 셋째 3V3와 왼쪽 커넥터 P9는 비워 둔다. ESP32 USB에서 `U`를 보내 실시간 모드로 전환한 뒤 115200 baud, 8N1에서 위치 갱신과 선 분리 후 위치 미확인을 시험한다.
5. **전자종이 화면 품질** — 교체 보드에서 이전 그림이 남은 위치를 확인한다. 새 화면을 밝은 곳에서 보고 하단 선명도, 빨간 출발점·구간명, 기존 글자 잔상을 확인한다. 부팅 후 기본값은 HOLD다. 실물 `?` 조회로 확인한 90.1초 동안의 갱신 횟수와 눈으로 보이는 선명도는 각각 기록한다. 패널 결합이 필요하면 전원을 끄고 큰 ESP32-L의 P3 전원 점퍼, P5·P2 양 끝(3.3V·BUSY), 작은 DESPI-C02의 P1 리본 잠금을 확인한다. GDEY075Z08의 RESE 설정은 0.47 Ω이다.
6. **통합 시연** — 관제 LED 4개 상태, S5 접근·이탈 시 부저, `ARRIVED` 뒤 키패드 0을 새로 눌렀을 때 문이 한 번 열리는지 확인한다. 화면 전체 갱신 중에도 이 동작이 계속되는지 본다.
