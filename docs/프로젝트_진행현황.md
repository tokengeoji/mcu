## 현재 진행 · SAVE 재개 (2026-11-27)

기존 SAVE를 다시 주제로 진행한다. 루트의 [`stm32/`](../stm32/), [`esp32/`](../esp32/)와 v6 제작도·전자종이 지도·배선 자료를 계속 사용한다. [남은 작업과 실물 시험 순서](../TODO.md)를 기준으로 이어간다. 전환 주제였던 [서보 회전식 초음파 탐지기](../ultrasonic-scan/)는 보관한다.

## 확정한 전자종이 펌웨어

사용자가 `mcu-epaper-monochrome-fix (2).zip`으로 구동한 실물 화면이 깨끗하고 선명하다고 확인했다. 해당 ZIP의 ESP32 스케치와 빌드 스크립트를 기준으로 확정했다. 원본 ZIP의 SHA-256은 `dccf3ecc9a5bc03b5e181f5551507604cee143769f3eec0fd842178268bee2d8`이다. [실물 기록과 재현 방법](epaper-monochrome-fix.md)

- **부품과 도구** · ESP32-L과 DESPI-C02에 Seeed SKU `104990861`(T075A04, UC8179, 800×480 흑백)을 연결한다. 작은 어댑터 P3의 RESE는 0.47 Ω이다. ZIP의 구동 환경은 Arduino CLI 1.6.0, Arduino-ESP32 3.3.12, Good Display의 GDEY075T7 흑백 예제, SPI 4 MHz다.
- **실물 로그** · 첨부 기록에서 첫 전체 갱신의 BUSY는 4,743 ms이고 절전 뒤 `completed refreshes=1`, `retained=1`이었다. 재부팅 후에는 `completed refreshes=0`, `retained=1`로 기존 지도를 유지했다. 화면에는 검은 이중 원 출발점과 점선 위험구역이 표시된다. [기대 화면](epaper-startup.png)
- **원본 대조** · 첨부 ZIP과 저장소의 STM32 파일 49개, ESP32 소스·빌드 파일 6개를 바이트 단위로 비교했다. SPL C 프로젝트의 IAR `EMB_FLASH` 재빌드는 오류·경고 0건이었다. ZIP에 들어 있던 이전 컬러 미리보기는 흑백판이 전송하는 800×480 프레임으로 교체했다. 독립 캡처 두 건의 48,000바이트가 일치했다.
- **확정본 재검증** · Arduino CLI 1.6.0과 Arduino-ESP32 3.3.12에서 스케치 컴파일을 확인했다. 프로그램 304,572바이트, 정적 RAM 22,492바이트다. PC 모의 시험에서는 완료 표식이 저장된 재부팅 시 0회 갱신, H 수동 재표시 및 U 전환을 확인했다. 이 작업에서 보드에 새로 전송하지 않았다.
- **남은 시험** · 흑백판에서 STM32를 연결한 `U` 모드의 위치·상태 수신, 이동 링이 지나간 자리와 부분 갱신을 시험한다. S1~S5 거리, v6 모형 보정, 경보 및 문 서보도 실제 모형에서 확인한다.

## 11월 25일 이전 구동 방식과 검증 이력

- **전자종이** · 부팅 시 GDEY075Z08 일반 3색 전체 갱신 한 번으로 고정 지도를 표시한다. 이전 버전에서 검정·흰색·지도를 연속 표시하던 과정을 줄였다. 전원 차단 명령 뒤 늦게 BUSY가 활성화될 때 깊은 절전 명령을 너무 일찍 보낼 수 있는 경로를 수정했다. 이는 당시 3색 후보판의 동작이다. 이후 위의 흑백판으로 실물 표시를 확인했다.
- **ESP32 검증** · Arduino-ESP32 2.0.17에서 CLI와 IDE용 독립 스케치를 각각 컴파일했다. 플래시 288,473바이트, 정적 RAM 21,720바이트다. PC에서 20분 동안 분할된 위치·상태 프레임 4,000개를 처리하는 동안 기본 HOLD는 한 번만 갱신했다. H 중복 입력 병합, A 재표시, U 부분 갱신과 전체 갱신 전환, 오류 후 READY 복귀를 확인했다. 제조사 드라이버에 전원 차단 뒤 2 ms에 BUSY가 활성화되고 150 ms에 풀리는 신호를 주입했을 때, 수정본은 151 ms에 깊은 절전 명령을 보냈다. BUSY가 계속 활성화된 경우에는 명령을 보내지 않았다. 이는 PC에서 재현한 타이밍 시험이다.
- **STM32·UART** · 기존 SPL C를 IAR에서 다시 빌드했다(오류 0, 경고 0). 기존 DFU와 HEX의 애플리케이션 15,876바이트가 일치했다. PC에서 실제 송수신 코드를 연결해 양방향 프레임과 오류 처리를 확인했다. 해당 빌드 시점에는 USB 보드를 연결하지 않았다.
- **모형·센서** · 당시 [스티로폼 제작도 v5](foam-v5.md)의 바닥 60×43cm를 검토했다. 이후 사용자가 확정한 최신 제작 기준은 [v6](foam-v6.md)(55×40cm)이다. [센서 RAW 기록 도구](../tools/measure-raw.ps1)로 빈 복도와 S1~S5 앞 표적을 차례로 기록한다. 줄자 거리와 센서 원점·방향을 실제 모형에서 확인한 뒤 보정값을 정한다. [배선 및 기록 방법](하드웨어_연결.md)

- **이전 빌드 환경** · Arduino-ESP32 2.0.17과 ESP32epdx 1.0.9로 3색 후보를 검토했다. 확정된 흑백판의 빌드 기준은 [ESP32·전자종이 버전 명세](esp32-eink-versions.md)에 있다.

## 완료한 작업

| 항목 | 결과 |
| --- | --- |
| Arduino IDE에서 열기 | Arduino CLI 1.6.0에서 검증한 Espressif 3.3.12 코어를 설치한다. 보드는 ESP32 Dev Module을 선택하고 `esp32/build.ps1 -PrepareIde`가 출력한 `ControlRoom.ino`를 연다. |
| STM32 | 한백전자 STM32F103RBT6용 C 펌웨어를 실습 자료의 STM32F10x SPL V1.0과 IAR 프로젝트에 통합했다. DFU 벡터 주소는 `0x08003000`이다. |
| 센서와 현장 제어 | 초음파 5개를 순차 측정한다. 키트 UART의 `RAW` 응답은 S1~S5 거리(mm)이며 무응답은 `-1`이다. S5는 부저를 제어한다. 경보가 꺼졌을 때 ECHO가 복구되면 거리 판정에 따라 `UNKNOWN`, `CLEAR`, `ACTIVE` 중 하나로 전환한다. S5 복구 검사는 PC에서 11/11 통과했다. |
| ESP32와 전자종이 | Good Display ESP32-L, DESPI-C02, Seeed T075A04 흑백판으로 고정 지도의 선명도와 재부팅 유지가 확인됐다. |
| STM32 피에조 시험판 | 실습 키패드와 PA6 PWM을 사용한다. 숫자 1~5 하나를 누르면 선택 센서의 새 유효 ECHO마다 40 ms 확인음을 낸다. 미보정 상태에서도 작동하며 S5 위험 경보의 연속음이 우선한다. 다섯 키, 무응답, 키 해제·전환, 기존 0 키와 경보 우선순위를 호스트에서 검증했다. |
| 빌드·전송 | STM32 IAR `EMB_FLASH` 클린 빌드 오류·경고 0건. 새 `C:\mcu\ControlRoom_STM32_센서검증.dfu`는 주소 0x08003000부터 15,876바이트다. 정적 SRAM 할당은 스택 예약을 포함해 1,940바이트다. 기본 미보정 상태에서 기존 시험판과 DFU 바이트가 같다. 실측값을 넣으면 S5 복구 수정이 적용되므로 다시 빌드한다. STM32 전송·실행은 사용자가 진행한다. 과거 CH340(COM4) 시험에 ESP32-D0WD rev.1.1이 기록됐다. 흑백 확정본을 구동한 포트는 첨부 기록에서 COM10이다. 직전 고정 버전(c767c16)의 빌드 크기는 플래시 288,481바이트·정적 RAM 21,712바이트였다. |
| 센서 입력 캡처 검증 | S1~S5 각각에 타이머 입력을 주입했다. 16비트 카운터 순환을 포함한 5,800 µs 펄스를 다섯 채널 모두 995 mm로 환산했다. 30 ms 기한 뒤 끝난 ECHO가 유효 거리로 처리되던 문제를 수정했다. 입력 캡처 65개와 관제·UART 65개 검사가 모두 통과했다. |
| UART 검증 | STM32 코드가 출력한 위치·상태 7줄을 PC에서 1~5바이트로 나눠 실제 ESP32 수신 코드에 전달했다. 손상 3줄을 폐기하고 별도 파서 시험에서 잘못된 입력 18개를 거부했다. ESP32가 출력한 `READY → ERROR → READY`를 STM32 수신 코드에 다시 전달해 상태 전송 2회와 키트 UART의 `ERR DISPLAY` 1회를 확인했다. 49.7일 이상 끊긴 경우에도 오래된 상태와 위치가 다시 나타나지 않았다. |
| 배선·배치 도면 | 펌웨어의 `stm32/hardware.c`에 있는 `sensor_pins[]`가 S1~S5의 GPIO 초기화와 타이머 입력 캡처를 함께 결정한다. 센서·보드별 배선표, 하드웨어 신호 구조도, 복도 센서·문·관제소의 배치 예시를 [하드웨어 연결 문서](https://github.com/tokengeoji/mcu/blob/main/docs/%ED%95%98%EB%93%9C%EC%9B%A8%EC%96%B4_%EC%97%B0%EA%B2%B0.md)에 정리했다. |

교체 전 보드의 USB 로그에는 STM32 위치(P)·상태(S) 수신과 흰색 지우기의 BUSY 응답 누락이 기록됐다. 교체 직후 사용자는 지도와 옛 버스 정보의 잔상을 확인했다. 직전 고정 버전(c767c16)에서 검정·흰색·지도 BUSY는 각각 10,158 / 10,159 / 10,160 ms였다. 고정 직후와 90.1초 후 `?` 응답은 모두 `HOLD completed refreshes=3`이었다. `U`에서 두 흑백 부분 갱신이 약 3.2초(누계 5), `H`에서 전체 지도 갱신이 10,159 ms(누계 6)였다. 이후 사용자의 실물 사진에서 고정 중에도 하단부터 회색 반전이 생기고 적색 도형이 사라졌다.

현재 ESP32는 고정 지도 완료 기록이 있으면 부팅 시 패널을 다시 구동하지 않는다. `?`는 모드·현재 부팅의 갱신 횟수·가동 시간·리셋 원인·유지 기록을 표시한다. `H`는 고정 지도 재표시, `U`는 실시간, `A`는 180초 간격 자동 재표시다. [확정 흑백 지도](https://github.com/tokengeoji/mcu/blob/main/docs/epaper-startup.png)

## 남은 TODO와 시험 순서

1. **부품·전원 확인** — 전원을 끈 상태에서 결선한다. HC-SR04P 공급 전압과 ECHO의 실제 HIGH 전압을 확인한 뒤 STM32에 연결한다. 확정 전자종이 장치는 ESP32-L·DESPI-C02·T075A04 조합이다.
2. **센서 5개 단품 시험** — 새 DFU를 실행하고 PA6을 PIEZO 입력에 연결한 뒤 키패드 1~5 중 하나를 누른 채 해당 센서 정면에 평평한 표적을 댄다. 키트 UART에서 9600 baud, 8N1로 `RAW`를 보내 대응 열의 거리 변화를 줄자와 비교한다.
3. **모형 보정** — 빈 복도와 표적이 있을 때의 거리, 센서 원점·방향·복도 길이를 잰다. S5 접근·해제 거리와 서보의 열림·닫힘 펄스 폭도 실측해 `stm32/site_profile.h`에 넣고 두 보드를 다시 빌드한다. 현재 기본값은 미보정이며 거리 원시값을 먼저 읽을 수 있다.
4. **실제 보드 간 UART** — ESP32-L의 USB-C를 위로 두고 오른쪽 빨간 버튼 아래의 노란 커넥터 P6를 찾는다. 위에서 첫째 SCL(10번 핀)에 STM32 PB11, 둘째 SDA(9번 핀)에 PB10, 넷째 GND(7번 핀)에 공통 GND를 꽂는다. 셋째 3V3와 왼쪽 커넥터 P9는 비워 둔다. ESP32 USB에서 `U`를 보내 실시간 모드로 전환한 뒤 115200 baud, 8N1에서 위치 갱신과 선 분리 후 위치 미확인을 시험한다.
5. **흑백 실시간 표시** — `U` 입력 뒤 유효한 STM32 좌표를 수신할 때 검은 이동 링과 이전 자리 복원을 확인한다. `H`로 고정 지도에 복귀하고, 필요하면 `?`로 모드·유지 상태를 기록한다.
6. **통합 시연** — 관제 LED 4개 상태, S5 접근·이탈 시 부저, `ARRIVED` 뒤 키패드 0을 새로 눌렀을 때 문이 한 번 열리는지 확인한다. 화면 전체 갱신 중에도 이 동작이 계속되는지 본다.
